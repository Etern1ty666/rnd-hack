# «Хватит» — прогноз денег для малого бизнеса

Прототип фронта для кейса «Сервис финансового прогнозирования для малого бизнеса». Название — рабочее: это главный вопрос, который задаёт себе предприниматель.

## Запуск

```bash
cd web && npm install && npm run dev
```

Откроется на http://localhost:5173. Сверху справа — переключатель из трёх демо-бизнесов, каждый в своём состоянии:

| Демо | Компания из датасета | Что показывает |
|---|---|---|
| IT-студия · ИП | C047 | жёлтый риск: зарплата и налоги совпадают в конце месяца, деньги зависят от оплат клиентов |
| Кофейня · ИП | C065 | всё спокойно, денег хватает |
| Кафе · ООО | C140 | красный разрыв: денег не хватит 19 октября |

## Демо-данные

`tools/build_demo_data.py` собирает JSON для фронта из выписок кейса:

```bash
python tools/build_demo_data.py <папка_датасета> web/src/data C047 C065 C140
```

Нужны `pandas` и `numpy`. Скрипт — упрощённая заглушка, чтобы интерфейс работал на настоящих выписках. Это не финальная модель:

- категоризация правилами по назначению и контрагенту; если назначение пустое, категория берётся по контрагенту;
- регулярные платежи: зарплата (аванс и расчёт), аренда, кредит, сервисы, вывод денег себе;
- ЕНП ставится на 28-е число, сумма берётся по позиции месяца в квартале;
- по каждому клиенту из «счёт № … от …» считается, через сколько дней после счёта он платит; «открытые счета из 1С» сгенерированы по этому ритму (демо-интеграция);
- выручка с карт, QR и кассы — среднее по дням недели за 8 недель с поправкой на сезонность год назад;
- Монте-Карло (1000 прогонов) даёт коридор P10–P90, затем коридор калибруется на бэктесте, чтобы в него попадало около 80% фактов;
- бэктест: 19 точек отсечения за 9 месяцев, сравнение с наивными моделями «остаток не изменится» и «как в прошлом месяце»;
- пропуски в выписке находятся по скачку остатка: остаток на конец дня не сходится с остатком вчера плюс движение за день.

## Раскладка

Как в банковском приложении:
- **Слева** — общий блок «Всего на счетах / Свободно» и счета карточками сверху вниз (иконка банка, остаток, название, откуда данные), внизу «Новый счёт». Клик по карточке открывает страницу счёта: название, остаток, «учитывать в прогнозе», удалить.
- **Справа** — «Главное»: статус, быстрые действия, подтверждение догадки, «Как успеть», график на месяц и кольцо «Операции за 90 дней» (траты / поступления).
- **Остальное — отдельные разделы** во вкладках: Платежи (список или календарь), Что если, Расходы, Точность. Настройки бизнеса — шестерёнка.
- **Новый бизнес** (меню в заголовке) и **новый счёт** (кнопка слева) — разные страницы. Новый бизнес строится по выписке с операциями; у нового счёта берём остаток — из выписки 1С или вручную.
- На телефоне всё в одну колонку: вкладки листаются, счета — лентой, на внутренних страницах колонка счетов скрыта.

## Без ручного ввода

- **Подтверждения в один тап.** Сервис сам угадывает крупные будущие платежи по выписке и спрашивает по одному: «Похоже, 6 октября — зарплата сотрудникам 80 тыс. ₽. Верно?» → «Да / Другая сумма / Не будет» (для клиентов — «Не заплатит», для вывода себе — «Не возьму»). Ответ сразу меняет прогноз и сохраняется. Логика — `lib/confirm.ts`.
- **Событие одной фразой.** «клиент обещал 300 тыс. 20-го», «в пятницу куплю кофемашину за 150к», «через неделю штраф 30 тыс» — сумма, дата и направление разбираются правилами (`lib/phrase.ts`), перед добавлением видно, как фраза понята. В продукте на это место встаёт языковая модель. Если фраза не разобралась — есть ввод по полям.

## Загрузка выписки из банка

«Добавить бизнес» → выбрать банк (Центр-инвест, Сбербанк, Т-Банк, Альфа, ВТБ, Точка, другой) → загрузить файл выписки **в формате 1С** (`1CClientBankExchange`, .txt). Такую выгрузку делают почти все банки: у Центр-инвеста — в «Бизнес-онлайн», у Сбера — в СберБизнесе.

Всё считается в браузере, файл никуда не отправляется:
- `web/src/lib/engine/parse1c.ts` — разбор файла: кодировка Windows-1251 / DOS / UTF-8, свой счёт из заголовка, направление операции по счёту плательщика и получателя, начальный и конечный остаток;
- `web/src/lib/engine/forecast.ts` — модель прогноза, перенесённая с Python один к одному: категоризация, регулярные платежи, ЕНП, счета клиентов, выручка по дням недели с сезонностью, Монте-Карло, бэктест и калибровка коридора. На выписке за 2 года — около 100 мс.

Без своего файла можно нажать «или взять пример»: в `web/public/samples/` лежат две выписки в формате 1С, собранные из датасета скриптом `tools/to_1c_format.py` (счета и БИК вымышленные):
- `centrinvest_1c.txt` — детский центр, ИП: впереди разрыв;
- `sber_1c.txt` — автосервис, ООО: всё спокойно.

Загруженные бизнесы хранятся в браузере (localStorage) и переживают перезагрузку.

## Тесты

```bash
cd web && npm test
```

Проверяют разбор фраз в события, разбор файла 1С (в том числе настоящей выгрузки в Windows-1251) и то, что модель в браузере даёт тот же результат, что Python-скрипт на той же компании: остаток, категории, регулярные платежи и налоги, выручку по дням недели, коридор.

## Как устроен фронт

Пользователь — типичный владелец малого бизнеса: одна карта, личные и рабочие траты вперемешку, бухгалтера нет, зарплату и закупки платит сам. Он думает не «остатком на счёте», а счетами. Поэтому главный экран — как в банковском приложении, одной колонкой:

1. **Плашка «Всего на счетах / Свободно»** — сумма по всем счетам и картам (иконки банков), сколько из неё отложено на платежи и сколько можно тратить.
2. **Статус одной строкой**: «19 октября не хватит на свет и связь» или «На все платежи хватает — без риска можно взять на себя до 80 тыс.».
3. **Как успеть** — до трёх шагов с галочками (только если есть риск). Отмечаешь шаг — всё пересчитывается.
4. **Платежи** — зарплата, аренда, налог, кредит, «на себя», крупные закупки. Напротив каждого: ✓ хватит, ! может не хватить, ✕ не хватит X. Если в один день несколько платежей, деньги раздаются по очереди: зарплата, налог, кредит, аренда, остальное.
5. **Деньги на месяц вперёд** — график остатка.

**Название бизнеса — заголовок экрана и переключатель.** В выпадающем списке: свои бизнесы (с цветной точкой статуса), «+ Добавить бизнес», а если бизнесов два и больше — «Сводка по всем»: общая сумма и свободные деньги, где проблема, список бизнесов и ближайшие платежи по всем сразу. Старт — с одним бизнесом (Кафе), остальные демо-выписки подключаются через «Добавить бизнес».

**Настройки бизнеса** (шестерёнка вверху): название, вид деятельности, ИП/ООО, система налогов (УСН 6%, УСН 15%, АУСН, патент, общая с НДС, ЕСХН или «определите сами»), счета в разных банках с остатками и переключателем «учитывать в прогнозе», неприкосновенный запас. Налоги по выбранной системе считаются в `lib/tax.ts`: выручка и расходы по месяцам → сумма → дата (ЕНП 28-го, АУСН 25-го), плюс НДФЛ и взносы за сотрудников. Основной счёт — из выписки кейса, остальные в демо добавлены с остатком вручную.

Остальное спрятано в панели: календарь, «А что если», «Куда уходят деньги» (вместе с «на себя»), точность прогноза, добавление платежа.

Бэкенд (пока скрипт) отдаёт «кирпичики»: ожидаемые потоки по дням, события с источниками и ширину коридора. Фронт пересобирает из них прогноз (`web/src/lib/model.ts`) при любом изменении без запроса к серверу.

```
web/src/
  App.tsx             главный экран и панели
  lib/model.ts        пересчёт прогноза, вердикт (ok / risk / gap), шаги «как успеть»
  lib/evaluate.ts     всё для экрана одного бизнеса: прогноз, шаги, платежи, свободные деньги
  lib/bills.ts        платежи со статусом «хватит / не хватит», строка статуса
  lib/settings.ts     настройки бизнеса, демо-счета, пересчёт данных под настройки
  lib/tax.ts          налоговый календарь по системам налогообложения
  lib/banks.ts        банки и их цвета
  lib/engine/         разбор выписки 1С и модель прогноза в браузере (+ тесты)
  components/
    BizSwitcher.tsx   название-заголовок и переключатель бизнесов
    Overview.tsx      сводка по всем бизнесам
    AddBusiness.tsx   добавить бизнес: загрузка выписки или демо
    Summary.tsx       плашка «всего / свободно» со счетами
    Settings.tsx      настройки бизнеса: налоги, счета, запас
    BankBadge.tsx     иконка банка
    Bills.tsx         список платежей
    ForecastChart.tsx график остатка
    ActionList.tsx    шаги с галочками
    Drawer.tsx        боковая панель
    MoneyCalendar.tsx календарь
    WhatIf.tsx        сценарии из кейса + «точка закроется»
    Hundred.tsx       «из каждых 100 ₽», включая «на себя»
    Clients.tsx       через сколько дней платят клиенты
    Trust.tsx         точность на истории, план-факт, что учтено
    AddEvent.tsx      ручной ввод одной фразой
```
