# «Хватит» — прогноз денег для малого бизнеса

Прототип фронта для кейса «Сервис финансового прогнозирования для малого бизнеса». Название — рабочее: это главный вопрос, который задаёт себе предприниматель.

## Запуск

```bash
cd web && npm install && npm run dev
```

Откроется на http://localhost:5173. Сверху справа — переключатель из трёх демо-бизнесов, каждый в своём состоянии:

| Демо | Компания из датасета | Что показывает |
|---|---|---|
| IT-студия · ИП | C047 | жёлтый риск: зарплата и налоги совпадают в конце месяца, деньги зависят от оплат клиентов |
| Кофейня · ИП | C065 | всё спокойно, денег хватает |
| Кафе · ООО | C140 | красный разрыв: денег не хватит 19 октября |

## Демо-данные

`tools/build_demo_data.py` собирает JSON для фронта из выписок кейса:

```bash
python tools/build_demo_data.py <папка_датасета> web/src/data C047 C065 C140
```

Нужны `pandas` и `numpy`. Скрипт — упрощённая заглушка, чтобы интерфейс работал на настоящих выписках. Это не финальная модель:

- категоризация правилами по назначению и контрагенту; если назначение пустое, категория берётся по контрагенту;
- регулярные платежи: зарплата (аванс и расчёт), аренда, кредит, сервисы, вывод денег себе;
- ЕНП ставится на 28-е число, сумма берётся по позиции месяца в квартале;
- по каждому клиенту из «счёт № … от …» считается, через сколько дней после счёта он платит; «открытые счета из 1С» сгенерированы по этому ритму (демо-интеграция);
- выручка с карт, QR и кассы — среднее по дням недели за 8 недель с поправкой на сезонность год назад;
- Монте-Карло (1000 прогонов) даёт коридор P10–P90, затем коридор калибруется на бэктесте, чтобы в него попадало около 80% фактов;
- бэктест: 19 точек отсечения за 9 месяцев, сравнение с наивными моделями «остаток не изменится» и «как в прошлом месяце»;
- пропуски в выписке находятся по скачку остатка: остаток на конец дня не сходится с остатком вчера плюс движение за день.

## Раскладка

Три колонки, как в приложении Claude, — бесшовно: один фон, без линий между колонками, края прокрутки растворяются.
- **Слева — только чаты**, как у Claude: сверху кнопка «боковая панель» и логотип «Хватит?» (нажать — новый чат) — меню сворачивается, тогда та же кнопка остаётся в левом верхнем углу: навели — меню показывается поверх страницы, пока курсор над ним; нажали — закрепляется (состояние запоминается); ниже «Новый чат» (без подложки), ниже история — чаты группами по бизнесам, группы сворачиваются. Название чата — первый вопрос, свежие сверху. Подсвечен только открытый чат (серым), при наведении — серым потусклее и «⋯» с меню: переименовать, удалить. Чат другого бизнеса открывает и сам бизнес. Пустой чат не плодится: «Новый чат» вернёт в него.
- **Сверху ничего нет**: ни заголовка, ни кнопок. На узком экране — только кнопки меню и сводки.
- **По центру — разговор с Vi, и всё о бизнесе — в нём.** Внизу всегда строка ввода: «+», текст, микрофон — или «отправить», когда что-то написано. На строке справа сидит робот Vi — поверх переписки, места над строкой не занимает. Разделы — Платежи (список или календарь), Что если, Расходы, Точность, Настройки, счёт, новый счёт — Vi показывает прямо в переписке живым блоком под ответом: по вопросу («покажи платежи», «открой настройки»), из «+» в строке ввода или по ссылкам в карточках справа. Отдельных страниц нет, кроме нового бизнеса.
- **Справа — сводка карточками**, как панель Environment у Claude: белая подложка без рамки, внутри просто строки «иконка — текст — значение». Карточки: «Бизнес» (свёрнутая — название справа; развёрнутая — название: нажать на него или на стрелку — меню с другими бизнесами, «Сводка по всем», «Добавить бизнес» и «Переименовать»; и система налогов — свой выпадающий список прямо в строке), «Счета» (всего со шкалой — отрезок цвета банка на каждый банк по его доле; счета — клик показывает счёт в чате; «Новый счёт» — тоже в чате; свёрнутая карточка показывает общую сумму справа), «Платежи» — по месяцам прогноза: у каждого месяца свой заголовок, он сворачивает месяц; сначала раскрыт только этот (октябрь), другие — нажать на месяц, что раскрыто — запоминается; свёрнутая карточка — только заголовок. Внутри месяца таймлайн: оплаченный — зелёная галочка, ещё нет — пустой кружок (жёлтый — может не хватить, красный — не хватит); кружок можно отметить самому. «Изменения» — свои события: иконка зелёный «+» — поступление, красный «−» — расход, сумма тем же цветом; свёрнутая показывает итог «+300 тыс. −180 тыс.»; кнопка отмены — с подтверждением. «Этот месяц» — тот, что идёт сразу после даты выписки. Заголовок сворачивает карточку; при наведении появляется ручка ⠿ — карточку можно перетащить (или стрелками с клавиатуры), порядок и свёрнутые запоминаются. Когда Vi отвечает про что-то из этого, карточка раскрывается, а её подложка на миг голубеет; «Изменения» и «Точность» появляются, когда о них зашла речь. Статус и «как успеть» — в чате.
- **Новый бизнес** — отдельная страница в центре: строится по выписке с операциями. Новый счёт подключается в чате: остаток — из выписки 1С или вручную.
- Меню видно от 900 px, сводка справа — от 1200 px. Уже — чат во весь экран, меню и сводка выезжают по кнопкам.

## Без ручного ввода

- **Подтверждения в один тап.** Сервис сам угадывает крупные будущие платежи по выписке и спрашивает по одному: «Похоже, 6 октября — зарплата сотрудникам 80 тыс. ₽. Верно?» → «Да / Другая сумма / Не будет» (для клиентов — «Не заплатит», для вывода себе — «Не возьму»). Ответ сразу меняет прогноз и сохраняется. Логика — `lib/confirm.ts`.
- **Событие одной фразой.** «клиент обещал 300 тыс. 20-го», «в пятницу куплю кофемашину за 150к», «через неделю штраф 30 тыс» — сумма, дата и направление разбираются правилами (`lib/phrase.ts`), перед добавлением видно, как фраза понята. В продукте на это место встаёт языковая модель. Если фраза не разобралась — есть ввод по полям.

## Vi — помощник

Vi — главная фича: робот сидит на строке ввода, справа, на любом разделе — и только там (в сообщениях и меню его нет). Глаза следят за мышью, а пока строка активна — за мигающим курсором в ней (с переносами и новыми строками); пока печатают, Vi ещё и тянется к тексту всем телом, а затихли — выпрямляется. Лампочка на антенне — цвет статуса бизнеса (зелёный, жёлтый, красный); пока Vi думает — глаза бегают, а от жёлтой лампочки расходятся волны сигнала; пока отвечает — улыбается.

- **Неуклюжий и милый.** Всё движение — на пружинах в одном кадре анимации: наклон, подскок, сплющивание при приземлении, болтающаяся антенна, дыхание. Поэтому переходы между состояниями не рвутся, а выражение глаз меняется через моргание.
- **Можно толкать.** Нажатие — толчок с той стороны, куда нажали: зажмуривается «> <», подлетает и плюхается как желе, антенна пружинит, покачивается как неваляшка и косится на толкнувшего. Толкают подряд — злится всё сильнее: со второго удара хмурится (верх глаз срезан клином), с третьего на экране вспыхивает «💢» и краснеет лампочка, он упирается навстречу, на четвёртом мелко кипит. Пятый за пару секунд — оглушён: глаза-спирали, лампочка горит красным. Перестали — за пару секунд остывает.
- **Можно погладить.** Плавно поводить курсором (или пальцем) по голове: жмурится от удовольствия «^ ^», краснеют щёчки, ластится к руке и тянется за ней, антенна гнётся под ладонью, тихонько мурчит и пускает сердечки. Злость сразу проходит, оглушённый приходит в себя. Быстрый проход курсором мимо не считается, а провести с зажатой кнопкой — не толчок.
- **Новый чат** — только приветствие и четыре подсказки, последняя — «Добавить новый платёж» (Vi объясняет, как записать платёж фразой, и даёт поля или QR).
- **Чат как у Claude.** Ответ печатается на глазах, под ним — платежи со статусом, шаги «как успеть» с галочками (прогноз пересчитывается сразу) и кнопки-подсказки, а нужная карточка справа всплывает. Кнопки — только у последнего ответа, пока ничего не отправили после него. Фраза «клиент обещал 300 тыс. 20-го» записывается в прогноз с кнопкой «Отменить». Каждый чат хранится в браузере.
- **Голосом.** Микрофон в строке ввода — голосовой режим, крестик в углу — обратно; вопросы и ответы попадают в ту же переписку.

Ответы считает `lib/vi.ts`: вопрос → намерение по правилам → ответ из настоящего прогноза. Ответ — только данные (текст, платежи, шаги, кнопки, какой раздел показать), поэтому на место правил можно поставить языковую модель с тем же форматом.

## Загрузка выписки из банка

«Добавить бизнес» → выбрать банк (Центр-инвест, Сбербанк, Т-Банк, Альфа, ВТБ, Точка, другой) → загрузить файл выписки **в формате 1С** (`1CClientBankExchange`, .txt). Такую выгрузку делают почти все банки: у Центр-инвеста — в «Бизнес-онлайн», у Сбера — в СберБизнесе.

Всё считается в браузере, файл никуда не отправляется:
- `web/src/lib/engine/parse1c.ts` — разбор файла: кодировка Windows-1251 / DOS / UTF-8, свой счёт из заголовка, направление операции по счёту плательщика и получателя, начальный и конечный остаток;
- `web/src/lib/engine/forecast.ts` — модель прогноза, перенесённая с Python один к одному: категоризация, регулярные платежи, ЕНП, счета клиентов, выручка по дням недели с сезонностью, Монте-Карло, бэктест и калибровка коридора. На выписке за 2 года — около 100 мс.

Без своего файла можно нажать «или взять пример»: в `web/public/samples/` лежат две выписки в формате 1С, собранные из датасета скриптом `tools/to_1c_format.py` (счета и БИК вымышленные):
- `centrinvest_1c.txt` — детский центр, ИП: впереди разрыв;
- `sber_1c.txt` — автосервис, ООО: всё спокойно.

Загруженные бизнесы хранятся в браузере (localStorage) и переживают перезагрузку.

## Тесты

```bash
cd web && npm test
```

Проверяют разбор фраз в события, разбор файла 1С (в том числе настоящей выгрузки в Windows-1251) и то, что модель в браузере даёт тот же результат, что Python-скрипт на той же компании: остаток, категории, регулярные платежи и налоги, выручку по дням недели, коридор.

## Как устроен фронт

Пользователь — типичный владелец малого бизнеса: одна карта, личные и рабочие траты вперемешку, бухгалтера нет, зарплату и закупки платит сам. Он думает не «остатком на счёте», а счетами. Поэтому главный экран — как в банковском приложении, одной колонкой:

1. **Плашка «Всего на счетах / Свободно»** — сумма по всем счетам и картам (иконки банков), сколько из неё отложено на платежи и сколько можно тратить.
2. **Статус одной строкой**: «19 октября не хватит на свет и связь» или «На все платежи хватает — без риска можно взять на себя до 80 тыс.».
3. **Как успеть** — до трёх шагов с галочками (только если есть риск). Отмечаешь шаг — всё пересчитывается.
4. **Платежи** — зарплата, аренда, налог, кредит, «на себя», крупные закупки. Напротив каждого: ✓ хватит, ! может не хватить, ✕ не хватит X. Если в один день несколько платежей, деньги раздаются по очереди: зарплата, налог, кредит, аренда, остальное.
5. **Деньги на месяц вперёд** — график остатка.

**Бизнесы — группами в меню слева.** У каждого цветная точка статуса, внизу «+ Добавить бизнес», а если бизнесов два и больше — сверху «Сводка по всем»: общая сумма и свободные деньги, где проблема, список бизнесов и ближайшие платежи по всем сразу. Старт — с одним бизнесом (Кафе), остальные демо-выписки подключаются через «Добавить бизнес».

**Настройки бизнеса** (Vi показывает их в чате — «открой настройки» или «+» в строке ввода): название, вид деятельности, ИП/ООО, система налогов (УСН 6%, УСН 15%, АУСН, патент — только для ИП, общая с НДС, ЕСХН; какая-то выбрана всегда, по умолчанию УСН 6%), счета в разных банках с остатками и переключателем «учитывать в прогнозе», неприкосновенный запас. Налоги по выбранной системе считаются в `lib/tax.ts`: выручка и расходы по месяцам → сумма → дата (ЕНП 28-го, АУСН 25-го), плюс НДФЛ и взносы за сотрудников. Основной счёт — из выписки кейса, остальные в демо добавлены с остатком вручную.

Остальное Vi показывает в чате: календарь, «А что если», «Куда уходят деньги» (вместе с «на себя»), точность прогноза, настройки; добавление платежа и разделы — в «+» строки ввода.

Бэкенд (пока скрипт) отдаёт «кирпичики»: ожидаемые потоки по дням, события с источниками и ширину коридора. Фронт пересобирает из них прогноз (`web/src/lib/model.ts`) при любом изменении без запроса к серверу.
